## ❌ What Failed
- **Nested `<button>` froze the whole tab.** First cut of the calendar's day cell was a `<button>` that rendered `EventPill` (also a `<button>`) inside it — invalid HTML. Chrome didn't just warn, it hung the renderer (`Page.captureScreenshot` timed out, tab became genuinely unresponsive) — this was **not** just a lint-level nit, it broke the page for real. **Fix**: day cell is a `<div role="button" tabIndex={0}>` with onClick + onKeyDown (Enter/Space), matching the `TableRow`-as-clickable-row pattern already used elsewhere (e.g. `Hotline.tsx`) — event pills stay real `<button>`s, no nesting. **Lesson: never nest an interactive `<button>`/`<a>` inside another one in this app; when a container needs its own click target *and* contains its own buttons, make the container a `div role="button"` instead.**
- The backend's `/api/calendrier/evenements` is slow in dev — consistently ~8–10s per call (confirmed via `curl -w "%{time_total}"` and matched in the browser's Network panel). Not a bug in the front end; just be patient when live-testing this endpoint and don't mistake the wait for a hang (see the actual hang above, which was a different, real bug).
- **`package.json` disappeared from disk mid-session** (not caused by my edits — file existed and was successfully edited earlier in the session, then later `tsc -b` failed because it no longer existed on disk; `git status` showed it as deleted in the working tree). Root cause unconfirmed (possibly an external tool/IDE action, not Claude). **Fix**: restored via `git show HEAD:package.json`, re-applied the one edit that had been made on top (`docs:update` script entry). **Lesson: if `tsc -b` suddenly throws vite.config.ts/CommonJS errors unrelated to your change, check `git status` for an unexpectedly deleted core config file before debugging the actual error message.**
- Interim design choice (now superseded): before the backend added real fields, Action/Résultat/dates were packed into a bracketed text header prepended to `description` (e.g. `[Téléphone Sortant — RDV reporté — RDV le 25/08/2026] ...`) so nothing was silently lost. This was explicitly a stopgap — now replaced by real structured fields. **Old interactions created during the stopgap window keep their bracketed-text format forever** (no migration done or planned) — the timeline UI must keep falling back to raw `description` display for rows where `actionType`/`resultat` are null.

## 🔑 Key Points to Remember
- **Auth is now real and load-bearing.** Every route past the login screen requires a session; `AppDataProvider`/`Layout`/all page routes only mount inside `AuthenticatedApp`, which `App.tsx`'s `AuthGate` only renders once `status === 'authenticated' && !mustChangePassword && profileCompleted`. Don't add anything that calls the API outside that gated tree (mirrors the `AppDataProvider` unconditional-fetch trap that motivated this structure).
- **`credentials: 'include'` is mandatory on every fetch** now that auth rides an httpOnly cookie — both `request()` and `fetchByteEndpointBlob()` in `api.ts` set it. If a new fetch call is ever added outside those two helpers, it needs the same option or it'll silently look like an unauthenticated 401/403 in a cross-origin dev setup.
- **`UtilisateurCourantDto.mustChangePassword`/`profileCompleted`** drive onboarding — both must be `false`/`true` respectively (i.e. cleared) before the real app shows. Backend enforces this too (403 on everything except `/api/auth/**`/`/api/mon-compte/**` while either is pending), so the frontend gates are UX, not the actual security boundary.
- **No admin UI for `POST /api/utilisateurs/{admUserId}/reinitialiser-mot-de-passe` yet** — wired in `api.ts` (`reinitialiserMotDePasse()`) but no screen calls it; there's no "Utilisateurs (admin)" area in the app at all currently. Revisit if/when an admin section is requested.
- **`/calendrier` is new** (prior session) — month-grid view of scheduled RDVs/visites, under the "Ventes" sidebar group (same reasoning as Hotline: it's driven by prospection interactions). `resultatCode` on `EvenementCalendrierDto` distinguishes visite vs rendez-vous; matched loosely (`.toLowerCase().includes('visite')`) via `isVisiteEvenement()` in `lib/domain.tsx` rather than an exact-string compare, so a future référentiel rewording doesn't silently break the badge color. Events have no time component in the current data (form only captures a date) — don't add a fake time display.
- **Spec file path changed this session**: it's now `docs/api-docsV4.json` (correct spelling). The old typo'd `docs/qpi)docsV4.json` (and its `.backup.json`) no longer exist — don't look for them. `scripts/update-api-docs.mjs`'s `TARGET_PATH` was updated by the user directly (not by Claude) to point at the new name; `BACKUP_PATH` inside that same script still has the old typo'd name (see bug #2 above).
- **`npm run docs:update`** (→ `node scripts/update-api-docs.mjs`) fetches `http://localhost:8080/api-docs` and overwrites `docs/api-docsV4.json`, with a `--url` override and `API_DOCS_URL` env var supported. Always diff before/after when re-running this — see workflow above.
- **The "describe the needed endpoint, don't invent it" pattern works well here.** When a UI requirement (e.g. the legacy Action/Résultat/RDV dialog) needs backend fields that don't exist yet, build what you can, describe the exact request/response DTO shape needed in plain terms, and the user's backend gets updated between sessions. Don't hardcode business enum values as a permanent solution if there's any chance a référentiel endpoint will show up — check first, ask second, hardcode-as-stopgap only as last resort (and say so in a comment).
